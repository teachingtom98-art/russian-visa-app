## 2024-05-15 - DOM-based XSS via Local JSON Import
**Vulnerability:** The application was vulnerable to DOM-based Cross-Site Scripting (XSS). The `app.js` file dynamically generated HTML for the task list using properties from the local JSON state (`task.title`, `task.hint`, `task.source`, `task.sourceUrl`, etc.) without adequate sanitization. Specifically, when a user imported a malicious JSON backup file, an attacker could execute arbitrary JavaScript within the application's context (e.g. `javascript:alert(1)` in `task.sourceUrl` or `<img src=x onerror=alert(1)>` in `task.title`).
**Learning:** The zero-dependency, local-first architecture relies heavily on IndexedDB and JSON state serialization. Trusting the local state without re-sanitization prior to DOM insertion is a dangerous anti-pattern. Just because data comes from a local file instead of a server API doesn't mean it's safe.
**Prevention:** All data inserted into the DOM, regardless of its origin (including local `localStorage` or imported JSON), must be sanitized. Apply `escapeHtml` for general text content and `sanitizeUrl` (enforcing `http:`/`https:`) for `href` attributes to prevent `javascript:` URIs.
