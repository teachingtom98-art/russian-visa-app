## 2024-05-24 - Cross-Site Scripting (XSS) via Unsanitized Values
**Vulnerability:** The application was vulnerable to Cross-Site Scripting (XSS) due to untrusted JSON state imports and missing HTML escaping of certain non-string values. While string fields were escaped correctly, numeric or boolean values bypass `escapeHtml` or throw runtime errors if not carefully type-casted, leading to a breakdown in standard sanitization flow. Furthermore, `href` attributes lacked URL scheme validation, opening vectors for `javascript:` URIs.
**Learning:** Even with an escaping function, missing explicit string coercion causes runtime crashes (`.replace is not a function`) that break the UI and potentially bypass sanitization logic, particularly with dynamic values arriving from malicious JSON imports.
**Prevention:** 1) Coerce all inputs passed into sanitization functions to strings (e.g. `String(str)`). 2) Introduce URL sanitization functions (like `sanitizeUrl`) specifically checking against a whitelist of valid schemes (e.g., `http:` and `https:`) before rendering URLs into `href` properties.
