## 2024-10-24 - Cross-Site Scripting (XSS) via Local Storage JSON Import
**Vulnerability:** The application allowed importing of session workspace states from a user-provided JSON backup file. In the `renderTaskList` function, variables like `task.title`, `task.hint`, `task.source`, and `task.guidance` read from this JSON were passed directly into `innerHTML` without sanitization. This allowed stored XSS if a user imported a malicious JSON file containing payload vectors. Furthermore, `task.sourceUrl` was injected into the `href` attribute directly, presenting a javascript: URL execution risk.
**Learning:** Even local-first applications without a backend must aggressively sanitize inputs from imported files (JSON state backups). Data coming from the local filesystem or IndexedDB should be treated as untrusted just as if it came from a remote API.
**Prevention:** Always wrap dynamically interpolated untrusted data in template literals with the existing `escapeHtml()` function before DOM insertion. Enforce safe URL schemes by wrapping dynamically generated `href` values in a `sanitizeUrl()` validator that strictly limits protocols to `http:` and `https:`.
