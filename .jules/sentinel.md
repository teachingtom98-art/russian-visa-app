## 2024-05-24 - Fix Stored XSS via Imported JSON State
**Vulnerability:** The application was vulnerable to Stored XSS via the imported JSON state backups. Untrusted data imported from a JSON backup was rendered directly into the DOM (in `renderTaskList` of `app.js`) without sanitization (e.g., `task.title`, `task.hint`, `task.sourceUrl`). Additionally, `javascript:` URIs could be injected via `task.sourceUrl`.
**Learning:** Even client-side only SPAs that rely on local storage or user-provided file imports are vulnerable to Stored XSS if the imported data structure contains executable payloads and is directly injected into the DOM using methods like `innerHTML`. The assumption that "local data is safe data" is flawed when the data source (imported JSON file) can be externally manipulated.
**Prevention:** Always sanitize data before DOM injection (`escapeHtml`), regardless of its local origin. Specifically, enforce a strict URL scheme whitelist (e.g., `http://` and `https://`) for attributes like `href` to prevent `javascript:` execution.
