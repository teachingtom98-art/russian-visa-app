## 2024-05-18 - DOM XSS in JSON State Import
**Vulnerability:** A DOM XSS vulnerability existed where untrusted data from imported JSON backups (`task.title`, `task.hint`, `task.source`, `task.sourceUrl`, `task.verifiedDate`, `task.guidance`, `task.standardName`) was directly injected into the DOM via `innerHTML` without proper escaping in `app.js`. Also, URL schemes were not validated, allowing `javascript:` URIs.
**Learning:** Even though `escapeHtml` was defined, it was not applied to the data before rendering. Because this is a local-first app using JSON exports as state sharing, users could be tricked into importing malicious state files (DOM XSS). It is crucial to enforce context-aware encoding—applying `escapeHtml` in the DOM rendering function, but leaving it unescaped when exporting to plain `.txt` files to avoid data corruption, and validating URL schemes on `href`.
**Prevention:** Always validate URL schemes (e.g. `sanitizeUrl` enforcing `http/s`), and always apply HTML escaping (`escapeHtml`) to any dynamic data just prior to DOM insertion, regardless of the data's perceived "local" origin.
