## 2024-05-30 - [XSS] Unescaped DOM Insertion and Nullish Input Crash in `escapeHtml`
**Vulnerability:** Several properties (`task.title`, `task.hint`, `task.source`, `task.verifiedDate`, `task.guidance`, `task.standardName`, and `attachedFileInfo.size`) were interpolated directly into the `innerHTML` of the task list items in `app.js` without proper sanitization. In addition, `task.sourceUrl` was injected into the `href` attribute without URL scheme validation. The `escapeHtml` implementation itself would crash if passed non-string data, like JSON imports (due to `(str || '').replace(...)` throwing if `str` is an object, number, or boolean).
**Learning:** Even when reading from local memory or JSON state backups, untrusted data can trigger XSS if not explicitly sanitized when injected into the DOM. The `escapeHtml` utility needs to be robust against all possible input types, including numbers or booleans. `href` attributes should validate the URL protocol to avoid `javascript:` scheme payloads.
**Prevention:** Use `String(str ?? '')` in the `escapeHtml` function to gracefully cast nullish inputs and non-string types. Apply `escapeHtml` aggressively to all variable interpolations inside HTML templates, and `sanitizeUrl` (checking for `http:` or `https:`) for all URL insertions. Keep `.txt` exports unsanitized to prevent adding HTML entities where plain text is required.
