## 2024-05-24 - Cross-Site Scripting (XSS) via Unsanitized Template Literals
**Vulnerability:** The client-side application heavily relies on vanilla JS template literals (`innerHTML`) to build the DOM. User-provided data (e.g., file names, session info) and complex nested state were interpolated directly into the HTML structure without adequate output encoding, leading to DOM-based XSS vulnerabilities. Additionally, `href` attributes weren't validated against dangerous protocols like `javascript:`.
**Learning:** Even simple client-side SPAs without server backends are vulnerable to XSS if they reflect user-supplied or locally stored data (like indexedDB state) back into the DOM using `innerHTML` without proper sanitization.
**Prevention:** Consistently apply output encoding (e.g., the `escapeHtml` utility) to all variables interpolated into HTML string templates. Implement strict URL protocol validation (`sanitizeUrl`) to allow only safe schemes (`http:`, `https:`) in link contexts to defend against protocol-based XSS attacks.
