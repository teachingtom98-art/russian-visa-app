## 2024-05-18 - Prevent XSS in Rendered Application State from Local JSON Restore
**Vulnerability:** When a user restores their application state from a JSON backup file (`handleFileRestore`), the JSON object containing task details (like title, hint, source, guidance) was rendered directly into the DOM using `li.innerHTML = ...` without any sanitization in `renderTaskList`. Since this application is local-first, the JSON import is the primary vector for untrusted data input, making it susceptible to XSS if a user opens a maliciously crafted backup file. Similarly, unvalidated `sourceUrl` properties could inject javascript: URIs.
**Learning:** Even in a purely local-first application without a backend, any mechanism that imports data (like a JSON backup) must be treated as untrusted input. Directly interpolating imported data into `.innerHTML` creates a high severity XSS risk.
**Prevention:** Always sanitize data before DOM insertion. I applied the existing `escapeHtml` function to all textual task properties (`task.title`, `task.hint`, `task.source`, `task.verifiedDate`, `task.guidance`) and introduced a new `sanitizeUrl` function to ensure `sourceUrl` only uses `http://` or `https://` schemes.
